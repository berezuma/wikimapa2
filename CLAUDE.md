# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Static single-page map of geolocated Basque Wikipedia (eu.wikipedia.org) articles. UI text and code comments are in Basque (euskara) — keep it that way. No bundler. Deployed as plain static files by GitHub Pages from `main` (repo `berezuma/wikimapa2`, site https://berezuma.github.io/wikimapa2/). Generated files (`css/tailwind.css`, `data/*.json`) are committed, so the site needs no build on deploy.

## Commands

```
python3 -m http.server 8000   # serve locally: http://localhost:8000/?lat=43.26&lon=-2.93&zoom=14
npm install                   # once, only needed for the CSS build
npm run build:css             # regenerate css/tailwind.css (Tailwind 3.4.17)
npm run build:data            # regenerate data/*.json from Wikidata (takes a few minutes)
npm test                      # unit tests for js/api.js (node:test, fetch mocked, offline)
npm run test:e2e              # browser tests in headless Chrome against the live APIs (needs network)
npm run test:e2e -- smoke.html   # a single e2e page from tests/e2e/
```

E2E pages (`tests/e2e/*.html`) load the app in an iframe and write `{checks, done}` JSON into `<pre id="result">`. `run.mjs` drives Chrome over CDP (`--remote-debugging-pipe`) in real time. Don't switch it to `--virtual-time-budget`: under virtual time, Leaflet's `flyTo` animation frames stall. The app's `map` is module-scoped, so tests control it only through the DOM and URL params.

ES modules and the `ehmuga.json` fetch require HTTP, so opening via `file://` does not work. URL params `lat`, `lon`, `zoom` set the initial view (the share button generates them).

**Rebuild the CSS whenever you add or change a Tailwind class** in `index.html` or `js/*.js`. Tailwind only emits classes it finds there, so a new class without a rebuild silently has no style. Classes built in JS strings must stay literal (no string concatenation) so the scanner sees them.

## Architecture

- `index.html` holds the markup plus a small custom `<style>` block (ids, Leaflet popup tweaks, filter-panel slide). Leaflet 1.9.4 is loaded from unpkg (SRI-pinned) as a global `L`, then `js/app.js` is loaded as an ES module.
- `js/api.js` covers all Wikipedia/Wikidata access and has no DOM or Leaflet dependencies; bounds are passed as plain `{north, south, east, west}`. `js/app.js` covers the map, markers and UI state.
- `ehmuga.json` is the Basque Country border: an array of `[lat, lon]` pairs drawn as one `L.polygon`.
- `data/` is generated by `tools/build-data.mjs`; never edit it by hand:
  - `kategoriak.json` maps each filter Q-id to all of its subclass Q-numbers (P279*). Filter categories come from the `data-category` attributes in `index.html`, which may hold several space-separated Q-ids. **After adding or changing a category checkbox, run `npm run build:data`.**
  - `artikuluak.json` holds every geotagged eu-wiki article in the border's bbox plus a margin, as `[title, lat, lon, types?, year?]`. Types are P31 Q-numbers. Year is the earliest of P571/P1619/P580/P1249; years below -10000 (geological) are dropped. The file powers the zoomed-out overview, all category filtering inside that bbox, and the timeline.
- Markers are keyed by **article title** everywhere: geosearch, SPARQL sitelinks, static data, popups (`/wiki/<title>` links) and `summaryCache`. They live in a `L.markerClusterGroup` (Leaflet.markercluster 1.5.3 from cdnjs, SRI-pinned; clustering stops at zoom 17), and `renderArticles` adds and removes them in batches.
- Data sources (in `js/api.js`), all called directly from the browser with `origin=*`:
  - Wikipedia API: `geosearch` (map markers), `opensearch` (search box), `extracts|pageimages` (popup summary, cached in `summaryCache`), `coordinates`.
  - Category filters always go through `filterByCategories`, which matches P31 types against `kategoriak.json` in the browser. Putting `P279*` in a SPARQL query instead takes 10–60 s and times out.
    - When the map center is inside the `artikuluak.json` bbox, filters use the static data at any zoom. This is instant, but only as fresh as the last `npm run build:data`. That freshness trade-off was the user's choice.
    - Outside that bbox, at zoom ≥ `MIN_FILTER_ZOOM` (12), `fetchAreaArticles` queries Wikidata SPARQL (`query.wikidata.org`) live for the padded view. It usually takes 1–5 s but sometimes 30 s or more. The result is kept in `areaCache`.
    - Outside the bbox and below that zoom, the map shows "zoom in".
    - Titles come from sitelink URLs, never item labels.
  - Wikidata API (`wbgetclaims`/`wbgetentities`): fallback location (P19 → P740 → P276 → P131) for searched articles without coordinates. These are drawn in the separate `indirectLayer`.
- Main flow: `moveend` → 500 ms debounce → `updateMapData()`. It aborts the previous in-flight request (`AbortController`), fetches geosearch, SPARQL or static overview results, then calls `renderArticles()`. That diffs markers by title (`markersByTitle`) instead of clearing them, and never removes a marker whose popup is open (popup autoPan triggers `moveend`).
- Geosearch limits: a bbox larger than ~400 km² returns `toobig`, and the maximum radius is 10 km. When the view is too large, `fetchGeosearchData` shows the static overview if the map center is inside its bbox. Otherwise it falls back to a 10 km circle around the center and shows a hint.
- All requests go through `fetchJson`, which throws on HTTP errors and on MediaWiki `{error}` bodies (`error.code` is preserved). Popups are built as DOM nodes with `textContent`, never HTML strings. User feedback uses `showMapMessage(text, timeout)` rather than `alert()`.
- Marker colours come from the filter panel. Each `.category-group` heading (`data-group` = kultura / natura / herriak) collects the subclasses of the checkboxes below it. `articleGroup()` matches an article's P31 types against those groups, falling back to `besteak`. Geosearch results carry no types, so types are looked up by title in `artikuluak.json`; `loadMarkerGroups()` recolours existing markers once that data loads. Colours are CSS variables (`--wm-*`) in `index.html`. Markers and clusters are `L.divIcon`s styled there; clusters keep the `marker-cluster` class, and the e2e tests rely on it.
- At zoom ≥ `PHOTO_ZOOM` (17, where clustering stops), markers with a Wikipedia thumbnail become round photo icons. `updatePhotoMarkers` fetches thumbnails for visible markers in batches of 50 and caches them in `thumbnails`. `refreshMarkerIcon` calls `setIcon` only when `marker.iconKey` changes. Marker-pane CSS for these icons needs the long `.leaflet-container .leaflet-marker-pane …` selector to beat Leaflet's `img { width: auto }`.
- "Harritu nazazu" (`surpriseMe`) picks a random article from `artikuluak.json`: within the active filters, or otherwise from articles in a coloured group. It sets `pinnedArticle`, which `renderArticles` always keeps on the map even when geosearch doesn't return it, then flies there and opens the popup.
- The intro (counter card, border-drawing animation and marker fade-in) runs only on the first visit without URL params and without reduced motion. The `localStorage` key `wikimapa-sarrera-ikusita` records that it ran. E2E runs use fresh profiles, so `delight.html` sees it.
- Don't `pkill -f` or `pgrep -f` with a pattern that also appears in your own command line: it kills the shell running the command. Stop a test server by its port (`ss -ltnp`) instead.
- The timeline (`timelineIndex !== null`) renders only dated articles from `artikuluak.json` with year ≤ the selected year, combined with any active category filters, and only inside the bbox. The slider indexes the sorted `timelineYears` array (quantile scale, not a linear year scale). It auto-plays on open, in about 12 s.
- Category checkboxes apply on `change` (there is no apply button). Active filters show as chips under the search box and as a count on the filter button. Panel counts are per current view and come from the static data.
- A search selection, or `?artikulua=<title>` on load, opens that article's popup once its marker is on the map (`pendingPopupTitle`). The share button adds `artikulua` while a popup is open.
- Accessibility: the search box is an ARIA combobox (arrow keys, Enter, Escape via `handleSearchKeydown`). The filter panel is `inert` while closed; open and close it only through `openFilterPanel`/`closeFilterPanel`, which handle focus and `aria-expanded`. URL params are range-checked by `numberParam`.
- Geosearch and opensearch both run on CirrusSearch, which limits concurrent searches per user. Aborted requests keep running server-side, so a quick follow-up request can get `cirrussearch-too-busy-error`. `searchApi()` retries that error with a backoff; route any new CirrusSearch-backed call through it.
